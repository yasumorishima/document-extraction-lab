# CLAUDE.md — document-extraction-lab

## What this is
The owner's public lab for getting data out of documents. Each topic lives in
its own folder under `topics/` with its own README, samples and results.
Topics are added over time; the repo is not tied to one method.

First topic: `topics/glyph-table/` — PDFs whose text cannot be extracted
(characters drawn as shapes, or fonts with no Unicode information). A
generative AI drafts a glyph→character table once, a human checks it, and
every run after that is a plain lookup: free, offline, the same every time,
nothing invented. Includes a comparison with a generative-AI API and notes
from trying related OSS projects.

## Evaluation practice (added 2026-11)
Lessons from Anthropic, "Building strong safety evaluations" (2026-11-13). What changes from the next evaluation on:
- **Main measure plus coverage, and a do-nothing arm first.** "Silent errors" can be gamed: an arm that outputs nothing scores 0. Always report "?", missing and held pages beside it, and first score a trivial arm (empty output, or the PDF's own text extraction) with the same scorer.
- **Check the scorer itself.** Before trusting `score_text.py` on a new condition, inject known changes (swap, drop or add N characters) into the truth and confirm it counts exactly those.
- **Write where the truth came from.** Self-made samples use the generator's input. The public report uses its own text layer before outlining. Truth is never a model's output. Re-read a random set of public-report lines by hand from the page image, without seeing the truth or any output, and report the mismatches. The draft-check numbers so far (e.g. "person checks 113") were simulated against the truth; measure the real check with a person who does not see the truth.
- **Split by character class.** Report digits, kana, kanji, Latin, punctuation and look-alike groups separately, including the ones that did not change.
- **Paired comparison for AI arms.** Run 3 or more times. Compare arms on the same pages through per-page differences with an interval, not only the range of totals. Claim a difference only when the interval excludes 0, and set the thresholds in the pre-registration.
- **Flag broken items.** API errors, empty or cut-off replies (max_tokens) and unparsable drafts are flagged, excluded and counted in the report. Never score them as 0 errors or as all wrong.
- **Possible training contamination.** Public issues published before a model's training cutoff may have been in its training data. Report AI results on those issues apart from later issues and self-made samples.
- **Record every setting.** Per run, record model requested/served, prompt, dpi, effort/thinking, the sha256 of the input PDF, the tool commit and the date. Compare two numbers only when every setting except one matches. Do not compare across scorer modes (`--loose` vs strict).

Added 2026-11-28 from Anthropic, "Migrating our Messages API to Rust" (2026-11-25; article read in full, items chosen for this repo):
- **Freeze the scorer, and show it.** AI-edited tests can pass by being weakened (the article found over 100 weakened assertions). Before reporting a pre-registered result, run `git diff <pre-registration commit> -- tools/score_text.py <the checker scripts>` and write in the results that it is empty, or list each change and why.
- **Read, do not guess, how another project works.** When describing another project's behaviour (options, defaults, what a setting controls), read its code or docs first and cite the file/line or page. Round 1 of docling went wrong on exactly this (font type, `images_scale`, the missed `replace_broken_text_layer`).
- **Copies of one post must match.** After changing a post, run `python topics/glyph-table/tools/check_post_copies.py <draft> <zenn copy> <qiita copy>` (title and body must match, no empty body). The English DEV.to version is a translation: change it by hand in the same commit set and say so.
