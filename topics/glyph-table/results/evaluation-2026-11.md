# 評価：帳簿方式 vs ふつうの OCR vs 生成 AI（2026-11-21〜22、第 8 版：回転・縦書き、向きと傾きの自動補正、保留を追加）

実行場所：Claude Code クラウド（x86_64）。すべてこのリポジトリのコードで再現できる（最後の「再現」）。
サンプルはすべて自作・架空。

> 実在の公開資料（総務省統計局「人口推計」月報）での評価は `public-evaluation-2026-11.md`。
> そこでは上位の生成 AI も誤り 0 で、帳簿方式との差は費用・毎回同じ結果・データを外に出さないことに出た。

## 結論
2〜12 月（11 か月分）を、1 月だけから作った帳簿で読んだ結果。「黙った誤り」＝印なしで別の字を出したもの。

| | 英語 5,259 字 | 日本語 4,207 字 |
| --- | --- | --- |
| **帳簿方式**（「?」の字を人がその都度足す） | **誤り 0**・? 17（12 月は 0） | **誤り 0**・? 61（12 月は 0） |
| **帳簿方式**（1 月の帳簿のまま） | **誤り 0**・? 114 | **誤り 0**・? 314 |
| ふつうの OCR（OCRmyPDF + Tesseract） | **誤り 126**・余分 4 | **誤り 249**・余分 166（全角半角の違いは除外） |
| 生成 AI（Claude 4 モデル × 3 回、似た字に注意する指示文） | **誤り 6〜54**（Opus 11〜15） | **誤り 192〜249**（Opus 192〜203） |
| 1 ページの費用・時間 | 帳簿方式 0 円・0.3〜1.5 秒／OCR 0 円・数秒／生成 AI 約 0.001〜0.19 ドル（モデルによる。Opus 約 0.03〜0.04 ドル・約 10 秒） | 同左 |

- 帳簿方式は、下の **17 条件のうち 16 条件で 11 か月間誤り 0**（英字フォント 4 種、日本語、実在の変換ツール Ghostscript、1 行まとめの図形、罫線が字に接する、字間を詰めた組版、引用符、座標の揺れ ±0.02／±0.05pt）。
- 唯一の例外は**極端な座標の揺れ（±0.1pt）**：誤り 25 字。その場合も帳簿を作る 1 月の時点で「同じ字どうしが違う字どうしより似ていない」と出るので、危ない PDF だと事前に分かる。
- 生成 AI は**どのモデルでも**（最上位の Fable 5.2 を含む）、英語の I/l、日本語のカ/力・ー/一 などを「?」と書いてよいと言っても迷わず決めて間違える。同じページを 3 回読ませて 3 回とも同じ結果になるページはほとんど無い。
  一方、I と l がはっきり違うフォントでは誤り 0、座標の揺れにも強い（±0.1pt で誤り 12、帳簿方式は 25）。
- **帳簿の下書き**は生成 AI に作らせ、人が確認する。下書きの誤りを確認せずに使うと、1 か所の誤り（l を I）が 11 か月で 210 字の黙った誤りになった。
  **4 モデル × 3 回の下書きを比べ、答えが割れたまとまりだけを人が見る**と、確認は英語 83 個中 5 個・日本語 90 個中 7 個で済み、多数決の誤りはすべてその中に入っていた（見逃し 0）。

## サンプル（`samples/make_variants.sh` で 17 種類 × 12 か月を作る）
架空の月次明細、A4 1 ページ × 12 か月、同じ書式。品番にわざと似た字を混ぜた（英語 0/O・1/l/I、日本語 カ/力・ロ/口・ニ/二・エ/工・ハ/八・タ/夕・ー/一）。
月によって初めて出る字がある（`%` `#` `Q` `B` `k` `J`、日本語では「備考」「振込」など）。

| 条件 | 中身 | フォント（ライセンス） |
| --- | --- | --- |
| outline | 字の輪郭を 1 字ずつ図形に | Liberation Sans（OFL 1.1）。I と l の差は高さ約 5% だけ |
| outline-merged | 1 行分の字を 1 つの図形に | 同上 |
| gs-outline | 文字情報を抜いたフォント版を Ghostscript 10.02.1 `-dNoOutputFonts` で図形に（実在の変換ツール） | 同上 |

## 帳簿方式のしくみ（`method/`、標準ライブラリのみ）
1. PDF の塗りつぶし図形を読む（`q`/`Q`/`cm` に対応）。細長い長方形（太さ 1.5pt 以下・長さ 20pt 以上）は罫線として外す。
2. 字形を小さな白黒画像にし、似ている度合い（重なりの割合）を測る。幅か高さの差が許容差を超えたら別の字。1 ピクセルずらした位置も試す。
3. **1 月だけで帳簿を作る**。字の確定は正解ファイルで代用（人の確認の代わり）。部品は「中心がどの字の枠に入るか」でまとめる（「i」の点、「明」の左右）。
   - 基準値と大きさの許容差は 1 月だけで決める（`pick_threshold.py`）。同じ字どうしが違う字どうしより必ず似ていればその中間、そうでなければ同じ字をまとめる側に寄せる。
   - 違う字が同じまとまりに入ったら「紛らわしい」として、以後そのまとまりは **`?`**。
   - この PDF が「1 図形 = 1 字」で描かれているかも 1 月から覚える。
4. 2 月以降は帳簿を引くだけ。図形はまず丸ごと照合し、合わなければ（1 図形に複数の字がある PDF のときだけ）部品の分け方を帳簿に一番よく合うように選ぶ。どこにも十分似ない形、まとまりの仲間より似ていない形は **`?`**。
5. 「目で確かめて」の印：出現が 3 回未満のまとまりで、形の近い別の字があるときだけ。

### 回転した文字・縦書き（2026-11-22 追加）
**回転**（`method/run_rotated.py`、`results/method/rotation-{outline,ja}-12months.json`）：各月のページの中身を `q <回転> cm … Q` で包み、絵ごと回した（中身は同じ）。2 通りの帳簿で 2〜12 月を読んだ。
- **同じ向き**：帳簿も、回した 1 月から作る（人が回った字形を確認する。字の確定は回す前の同じ図形から）。
- **まっすぐ**：帳簿は回す前の 1 月から作り、回したページを読む。

採点は図形 1 つずつ：照合の答えと、その図形の正解を比べる（読む順番に左右されない）。あわせて、ふつうの順番つき採点で正しかった字の数も出した。

| 回転 | 同じ向き：誤り / ? | 同じ向き：順番どおり正しい字 | まっすぐ：正しい / **誤り** / ? | まっすぐ：ページごとの ? の割合 |
| --- | --- | --- | --- | --- |
| 英語 0° | 0 / 114 | 5,145 | 5,145 / 0 / 114 | 1〜3% |
| 英語 1° | 0 / 114 | 3,971 | 1,589 / 0 / 3,670 | 66〜73% |
| 英語 3° | 0 / 114 | 3,302 | 114 / 0 / 5,145 | 98% |
| 英語 90° | 0 / 114 | 670 | 0 / 0 / 5,259 | 100% |
| 英語 180° | 0 / 114 | 568 | 1,296 / **171** / 3,792 | 68〜76% |
| 英語 270° | 0 / 114 | 476 | 0 / 0 / 5,259 | 100% |
| 日本語 0° | 0 / 314 | 3,893 | 3,893 / 0 / 314 | 4〜10% |
| 日本語 1° | 0 / 314 | 2,792 | 243 / 0 / 3,964 | 93〜95% |
| 日本語 3° | 0 / 314 | 2,355 | 45 / 0 / 4,162 | 98〜100% |
| 日本語 90° | 0 / 314 | 461 | 0 / 0 / 4,207 | 100% |
| 日本語 180° | 0 / 314 | 259 | 757 / **61** / 3,389 | 77〜85% |
| 日本語 270° | 0 / 314 | 468 | 0 / 0 / 4,207 | 100% |

- **向きがそろっていれば、どの角度でも字形の照合は 0° と同じ**（誤り 0、? も同じ数）。
- ただし**読む順番**は「横に並んだ行」を前提にしているので、回したページでは崩れる（90°・180°・270° で順番どおり正しい字は 5,145 字中 476〜670 字。1°・3° でも行が傾いて崩れる）。直すにはページの向きを知る必要がある（その後、向きと傾きの自動補正を実装した。下の「ページの向きを直す」以降の節）。
- **まっすぐな帳簿で別の向きのページを読むと**、1°・3°・90°・270° はほとんどが「?」になり、誤りは 0。
- **180°（上下逆）だけは黙った誤りが出る**：英語 171 字（n↔u 112、6↔9 37、(↔) 22）、日本語 61 字（6↔9 39、（↔）22）。上下に回すと別の字とまったく同じ形になる字があるため。正しく読めた字も、o・0・8・S・N・Z のように回しても同じ形の字が偶然合っただけ。
- **止め方（案）**：上下逆のページでは、字の 68〜85% が「?」になった。ふつうのページの「?」の割合は最大 15% だった（自作 16 条件と、実在の月報の 1〜10 月号）。
  - 「? が 3 割を超えたページは丸ごと人に回す」決まりにすれば、今回の上下逆のページはすべて止まる。
  - 同じ決まりで、極端な揺れ（±0.1pt、42〜48%。誤り 25 字が出た条件）の全ページと、書式が変わった月報 11 月号の 1〜5 ページ（40〜88%）も止まる。11 月号の 6 ページ（0.5%）は止まらない。
  - ただし **3 割という値は結果を見てから決めた**もので、事前に決めた検証ではない。
  - （その後、この値を事前登録で固定し、まだ試していない条件で確かめた。下の「ページの向きを直す」以降の節）

**縦書き**（`samples/make_sample.py --lang=ja --vertical`、`results/method/ja-vertical-12months.json`）
- **作り方**：日本語の明細の表を回して、行を列にした（列は右から左、字は上から下）。「ー」「、」「。」「「」」「（）」は、フォントの縦書き用の字形（GSUB `vert`）にした。半角数字は 1 字ずつ縦に立てた（実際の縦書きの書類では横に寝かせることもある。それは「回した字」と同じ扱いになる）。
- **読み方**：`method/run_method.py … --vertical` で、列を右から左、列の中を上から下へ読む（`read_page.read(vertical=True)`）。帳簿を作るときに、人が縦書きだと指定する。
- **結果**：**横書きとまったく同じ**。誤り 0、? は 314（1 月の帳簿のまま）／61（「?」の字を人がその都度足す）。順番どおりの採点でも同じ。
- **直した所**：人の確認の代わりに正解の枠で字形を割り当てる所で、枠の高さが横書き用（字の大きさの 1.35 倍）だった。縦に 1 字ずつ並ぶと隣の枠と重なり、1 月の「）」が割り当てられていなかった。縦書きの行は、枠を字の大きさ 1 つ分にした。横書きの結果は変わらないことを確かめた（outline と ja で 11 か月分の数字が同じ）。

### ページの向きを直す・「?」の多いページを止める（2026-11-22、事前登録つき）

- **実在の月報**：上下逆にした 66 ページすべてで向きを直し、まっすぐな時の結果と完全に同じだった。
- **90° 単位でない回転（2°・45°・-1°）**：
  - 揺れの無い条件では、すべてのページが保留になった。
  - **揺れのある 2 条件では、保留されないページが出た**。そのページで字の順番が崩れ、事前登録の判定は**不合格**。

### 傾いたページをまっすぐに戻す（2026-11-22、事前登録つき、一部不合格）
事前登録：`results/preregistration-skew-2026-11.md`（結果と理由もそこに書いた）。
- **やり方**：大きさの近い一番近い輪郭どうしを結んだ線の角度の中央値で、ページの傾きを測る。逆に回してまっすぐにしてから、向きを直して読む。
- **わずかな傾き（0.5°・-2.5°・7°）**：罫線の無い条件では、回さない時と同じ結果になった。前の H2 で外れた揺れのある PDF も、誤り 0 になった。
- **外れたところ**：
  - **罫線のある条件**：罫線を取り除く処理が傾きを戻す前に動くので、傾いた罫線が「?」として残る。
    - 実在の月報（1.5°・178°）も同じで、余計な字は 0 だったが、「?」が 6% 増えた。
  - **40°・130°**：傾きの測り方の精度が足りない。「?」が増え、測り違えたページは保留された。保留されないページで出た誤りは、揺れのある 1 条件で各 2 字。
- **次の改善**：罫線の処理を、傾きを戻した後にも行う。傾きを細かく合わせ直す（または大きな傾きは保留にする）。

### 傾き対応の 3 回目：罫線を戻した後にも取り除く・大きな傾きは保留（2026-11-22、事前登録つき、すべて合格）

## まだ言えないこと
- 実在の PDF の「揺れ」の大きさは未測定（Ghostscript の出力は同じ字どうしが 0.9992 まで一致）。
- 人の確認作業は正解ファイルで代用。実際の手間と人の間違いは測っていない。
- 1 つの図形の中で左右に分かれた字（`"`）は、1 月に出ていれば正しく読めた。1 月に出ない場合は未確認。
- 回転：90° 単位の向きは自動で直る（事前登録で確認）。10° 以下の傾きは測って戻して読める（罫線のある表を含む。判定に使った角度は 0.3°・-4°・9°・95°。揺れの無い条件では回さない時と同じ結果、揺れのある条件と実在の月報では「?」がわずかに増えた）。10° を超える傾きは保留にして人が見る（読まない）。
- 縦書きは自作の 1 条件だけ。半角数字を寝かせた縦書き、縦横が混ざったページは未測定。
- Form XObject 内の文字、画像の文字は対象外。
- 生成 AI は Claude の 4 モデルだけ。ふつうの OCR は Tesseract だけ。
