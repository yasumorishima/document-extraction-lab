# 評価：docling の「ページ全体を OCR し直す」回避策（2026-11-24）

> 第 2 回（壊れた文字の層を置き換える `replace_broken_text_layer`、既定の OCR エンジン、帳簿方式を同じ PDF で）は `results/preregistration-docling2-2026-11.md` で事前登録し、結果は末尾の「第 2 回」。**投稿に使うのは第 2 回の結果。**

事前登録：`results/preregistration-docling-2026-11.md`（実行前に main に入れた）。実行場所：Claude Code クラウド（x86_64）。
出力と設定：`results/oss/docling/`（各 `run.json` に版・設定・入力 PDF の sha256・時間）、集計 `results/oss/docling/summary.json`（`tools/summarize_docling.py`）。

## 何を確かめたか
docling issue #2963（未解決、2026-11-24 時点でメンテナーの返事なし）と、関連する #2170・#3081・#3582。
文字の対応表（ToUnicode）がないフォントの PDF は、docling の既定では文字化けする。issue で示された回避策は、Tesseract でページ全体を OCR し直すこと（`force_full_page_ocr=True`）で、コメントでも「これしか道がない」とされている。
その回避策で、似た字が黙って置き換わるかを測った。

- サンプル：自作の明細（`samples/make_sample.py` の `font` モード。Type0 フォント、CIDFontType2、`/Encoding /Identity-H`、`/CIDToGIDMap /Identity`、ToUnicode なし。埋め込み TrueType には cmap 表もグリフ名もない）。英語（Liberation Sans）と日本語（IPAゴシック）、各 12 か月のうち 2〜12 月を採点。
- issue と同じ種類のフォント（Type0/CID、Identity-H、ToUnicode なし）。2026-11-24 訂正：最初の版は「こちらは単純な TrueType」と書いていたが誤り（生成スクリプトを読み直して確認。事前登録の第 1 回にも同じ誤りがあり、凍結のため第 2 回の事前登録に訂正を書いた）。
- 版：docling 2.152.0、docling-parse 7.27.1、docling-core 2.108.0、docling-ibm-models 4.0.4、Tesseract 5.3.4（eng・jpn）。
- 回避策の設定は issue のとおり：`do_ocr=True`、`TesseractCliOcrOptions(force_full_page_ocr=True, lang=[eng|jpn])`、`images_scale=2.0`、`do_table_structure=False`。OCR の解像度は `images_scale` ではなく OCR 側の `scale`（既定 3.0 = 216 dpi）で決まるので、Tesseract は scale 3.0 で動いた（2026-11-24 追記）。2 回実行した。

「余分」は、docling が表を Markdown で書く区切り線（`|---|`）を除いた数。この除き方は出力を見てから決めた（事前登録には無い）。除かない数は `summary.json` にある（英語 606、日本語 7,108。ほぼ全部が区切り線の `-`）。置き換えの数はどちらでも同じ。

**置き換えの中身**

- 日本語 330 字：0→9 89、一→ー 82、力→カ 27、二→ニ 24、工→エ 23、夕→タ 22、0→6 21、口→ロ 20、八→ハ 13 など。漢字 213、数字 110。日付・品番・金額の 0 が 9 や 6 になる（2 月号では金額 `10,908` が `19,908` に）。

## 言えること・言えないこと
- issue の回避策で文字化けは消えるが、代わりに似た字の置き換えが黙って入る。全体の字数に対して英語 2.6%、日本語 7.8%。出力には印が無いので、使う人は気づけない。

## 第 2 回：壊れた文字の層の置き換え（`replace_broken_text_layer`）（2026-11-24）

事前登録：`results/preregistration-docling2-2026-11.md`（実行前に main に入れた、PR #25）。出力 `results/oss/docling/round2/`、集計 `results/oss/docling/round2/summary.json`。

docling 2.152.0 には、#2963 が求めている機能がすでに入っている（PR #4654、2026-10-27 マージ、既定では無効）。`replace_broken_text_layer=True` にすると、文字の層が壊れていると判定したページだけを OCR で読み直す。判定は `docling/utils/text_quality.py` の `is_broken_text_layer`（U+FFFD や制御文字の割合、英字の母音の少なさなど）。

### 判定：壊れたページを見つけたか
| サンプル | ページ数 | 壊れていると判定 |
| --- | --- | --- |
| 自作 英語（ToUnicode なし） | 11 | **11** |
| 自作 日本語（ToUnicode なし） | 11 | **11**（Tesseract の設定で。既定エンジンは日本語で動かず、下記） |
| 自作 英語、文字を 3 つずらした ToUnicode（"the" → "wkh"） | 11 | **0** |
| 人口推計 月報の元の PDF（正常な文字の層）1〜5 ページ × 11 か月 | 55 | **0**（既定エンジンの設定）／CONTROL_TESS（Tesseract の設定） |

### 置き換えた後の読み取り（2〜12 月、置き換え＝誤り）
| 設定 | 英語 5,259 字 | 日本語 4,207 字 |
| --- | --- | --- |
| 既定エンジン（`OcrAutoOptions`。選ばれたのは RapidOCR、torch 版、ラテン文字モデル）2 回 | **113**（2 回同じ） | 動かない：標準のインストールでは日本語を読めるエンジンが無く、11 件とも `OcrLanguageNotSupportedError`（数えたが採点はしていない） |
| Tesseract、scale 3.0（既定）2 回 | **137**（2 回同じ） | **328**（2 回同じ） |
| Tesseract、scale 2.0 | 142 | 429 |
| Tesseract、scale 4.0 | 130 | 283 |
| 文字を 3 つずらした英語（既定エンジン・Tesseract とも） | 壊れていると判定されないので OCR されず、ずれた文字がそのまま出る（正しい字は 5,259 字中 347 字） | — |
| 帳簿方式（同じ PDF を Ghostscript で図形にして、1 月の帳簿で 2〜12 月） | **0**（「?」114） | **0**（「?」314） |

- 既定エンジン（RapidOCR）英語 113 字：l→I 48、O→0 36、6→9 10、I→1 9、l→1 7、9→6 3。英字 100、数字 13。
- Tesseract 日本語 328 字：0→9 89、一→ー 82、力→カ 27、二→ニ 24、工→エ 23、夕→タ 22、0→6 21、口→ロ 20、八→ハ 13 など。漢字 211、数字 110。
- 採点は事前登録どおり、Markdown の表の区切り線を除いてから。日本語の置き換え設定の「余分」（1 か月 40 字ほど）は、表の下の 1 行（`備考：税込（８％）`）が表の 5 列すべてに繰り返されたもの（表の構造を読む処理。読み違いではない）。置き換えの数には影響しない。

### 事前登録との照合
- **F3（成立）**：対応表のない自作 22 ページは、すべて壊れていると判定された。
- **F4（成立）**：置き換えた後も、英語で既定エンジン 113 字・Tesseract 137 字が黙って置き換わる（O/0、I/l/1 を含む）。解像度を 2.0〜4.0 に変えても 130〜142 字。
- **F5**：正常な人口推計 55 ページは、既定エンジンの設定で 0 ページが誤判定。Tesseract の設定は CONTROL_TESS_F5。
- **F6**：文字を 3 つずらした対応表（#2963 で tseaver さんが報告した形）は、11 ページとも壊れていると判定されず、ずれた文字がそのまま出力された。
- **F7（成立）**：帳簿方式は同じ PDF で英語・日本語とも 0。

### 言えること・言えないこと
- #2963 の「自動で見つけて OCR に回す」は、docling 2.152.0 で `replace_broken_text_layer=True` として使える。対応表が無いページは確実に見つかり、正常な 55 ページは誤判定されなかった。
- ただし回した先の OCR は、品番や数字の似た字を黙って置き換える（英語で 2〜3%、日本語で 7〜10%）。解像度を上げても大きくは減らない。
- 文字がずれた対応表（文字には見えるが中身が違う）は判定をすり抜ける。この形は今の判定では見つからない。
- 日本語は、標準のインストールでは既定エンジンが動かない（Tesseract などを明示すれば動く）。
- 自作サンプル（英語・日本語、各 11 か月）と正常な公開 PDF 1 種類だけ。他の OCR エンジン（EasyOCR、onnxruntime 版の RapidOCR、Nemotron）は入れていないので測っていない。
