# 非エンジニア向けの説明の材料と、今後の方針

評価（`results/` の 3 つの文書）が終わった時点で、人に説明するときの要点と、これからやることをまとめる。
数字はすべてこのリポジトリで測ったもの（自作サンプルと、総務省統計局「人口推計」月報）。

## 1. 一言でいうと
**「一度だけ字の見本帳（帳簿）を作れば、あとは何度でもタダで、毎回同じに読める」読み取り方。**

文字が「文字」として入っておらず、形（図形）として描かれている PDF がある。コピーしても文字が取れない。
ただし同じ文字はいつも同じ形で描かれるので、「この形は A」という帳簿を一度作れば、
あとは形を帳簿と照らし合わせるだけで文字に戻せる。

## 2. 流れと役割
1. **形でまとめる**（プログラム）：同じ形の字をまとめる。1 か月分の月報（約 1.5 万字）でも、まとまりは約 1,000 個。
2. **まとまりに文字を当てる＝帳簿の下書き**（生成 AI）：まとまりの見本を並べて読ませる。昔はここを人が全部やっていたのが一番の壁。
3. **人が確認する**：4 つの生成 AI に下書きさせ、**答えが割れた所だけ**人が見る（月報では約 1 割）。
4. **毎月読む**（プログラムのみ、AI なし）：帳簿と照らし合わせるだけ。

## 3. 何がうれしいか（測った結果から）
- **毎回の費用がかからない。** 生成 AI に毎回読ませると、上位モデルで 1 ページ約 0.07〜0.22 ドル（月 1 万ページなら 690〜2,150 ドル）。帳簿方式は最初の 1 回だけ。
- **毎回同じ結果。** 生成 AI は同じページでも回によって答えが変わった。
- **資料を外に出さない。** 手元の PC だけで読む。
- **黙って間違えない。** 帳簿に無い形・紛らわしい形は「?」として知らせる。実在の月報 15 万字・自作サンプル 17 条件のほとんどで、黙った誤りは 0。
- 正直に言うべきこと：**ふつうの資料なら、上位の生成 AI も正確に読める**（実在の月報で誤り 0）。精度で勝つのは、紛らわしい字が多い資料（I と l がほぼ同じフォント、カ/力 を混ぜた品番など）。そこでは生成 AI は迷わずどちらかに決めて間違えた。

## 4. 不安な点：隠さず伝える
- **帳簿が間違っていると、毎月同じように間違える。** 一番成績のよい生成 AI の下書きでも、確認せずに使うと 11 か月で 200 字の誤りになった。人の確認は省けない（ただし割れた所だけでよい）。
- **書式が変わると「?」が増える。** 月報の 11 月号で数字の大きさが変わったとき、その月の数字はほぼ全部「?」になった。黙って間違えはしないが、人が新しい形を一度確認する必要がある。
- **形が大きく揺れる PDF は苦手。** 座標を極端に揺らした試験では誤りが出た（そのときは帳簿を作る段階で「危ない」と分かる兆候が出る）。
- **データが薄い字を知らせる。** 数回しか見ていない字で、しかも形の近い別の字があるものは「目で確かめて」と印を付ける。

## 5. これからやること
- **非エンジニア向けの説明資料**：上の 1〜4 から作成済み（`../explainer-ja.md`、2026-11-22）。
- **関連 OSS 2 件への投稿**（pdf-glyph-mapping の不具合報告と修正案、CUNY pdf-accessibility-app への結果共有と提案）。文面はオーナーの確認後。
- **シビックテックへの参加**：Code for Japan のような市民の IT ボランティアで、「文字が取れない行政 PDF」に困っている人がいるかを聞く（Slack やイベント。オーナー本人の参加が必要）。
- 関わって得たことは、他人のコードを写さず、「何が効いたか・どこが危ないか」を自分の言葉でこのリポジトリに残す。
- 守ること：使うのは自作サンプルと公開資料だけ。投稿先のライセンスと参加ルールを先に読む。

## 6. 調べた関連の取り組み（2026-11-21 時点、詳しくは `oss-verification-2026-11.md`）
- **pdf-glyph-mapping**（MIT）：字形を画像で並べ、人が対応表を書く。作者は「ほぼ放置」としている。
- **CUNY pdf-accessibility-app**（AGPL-3.0）：文字情報の無いフォントの字形を OCR の多数決で決める。活発に更新中。
- **sci2audio** issue #618（GPL-3.0）：互換フォントの字形と形で照合する計画（参加者はほぼ 1 人）。
- 文字が完全に図形の PDF を形でまとめて読む OSS は見つからなかった。
- Code for Japan の GitHub には該当するプロジェクトが無かった。行政 PDF から数字を取りたい需要の例として、総務省の PDF から表を抜き出すダッシュボード（`codeforjapan/mynumbercard_statistics`、MIT）がある。
